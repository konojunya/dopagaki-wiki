# dopagaki-wiki 実装プラン

## 目的

GitHubリポジトリの機能や一般的な技術概念について、質問に対する正確な説明を、スライド・音声・字幕付き動画として生成するskillとCLIを作る。

実行環境はユーザーのmacOS。説明の網羅性を優先し、短縮のために重要な内容を省略しない。スライドが増えることや動画が長くなることは許容する。音声だけでも、字幕付きの無音視聴でも理解できることを目指す。

この文書は実装前の計画であり、以下のCLI・型・ファイル構成は提案仕様。実装済みの機能を示すものではない。

## 決定事項

| 項目 | 方針 |
| --- | --- |
| 主言語 | TypeScript / Node.js |
| 調査・原稿 | skillを実行するエージェントが担当 |
| 動画生成 | 構造化データを受け取るCLIが担当。MVPではLLM APIを組み込まない |
| スライド | HTML/CSSの固定テンプレート。必要に応じてReactの静的HTML出力を利用 |
| 撮影・検査 | Playwright + Chromium |
| 音声 | ローカルのVOICEVOX ENGINE HTTP API。初期音声はずんだもん |
| 動画 | FFmpeg。音声時間の確認にffprobe |
| 字幕 | 読み上げ原稿と同じデータから生成し、動画に焼き込む |
| 動き | MVPは静止スライドの切り替え。トランジション不要 |
| 配置 | absolute/fixed禁止。通常フロー、Grid、Flexを利用 |
| 分量 | 内容が収まらなければ意味の通る複数ページに分割。文字縮小で回避しない |

RemotionはMVPでは採用しない。静止スライドごとに一度撮影し、動画化をFFmpegに任せる。将来は同じ中間データに別レンダラーを追加できるようにする。速度上の優位性は実測で確認し、未計測の倍率を約束しない。

## MVPの範囲

- リポジトリの指定機能を、spec・実装・テストの根拠付きで説明する。
- 一般的な概念も、調査部分を置き換えて同じ生成処理を利用する。
- 日本語、1920×1080、30fps、H.264/AACのMP4を初期出力とする。
- 要点、比較、処理フロー、コード＋説明、具体例の5テンプレートを用意する。
- 短文単位の音声生成、字幕同期、スライド前後の無音を実装する。
- HTMLプレビュー、MP4、字幕ファイル、原稿・根拠・検査結果を出力する。
- キャッシュと途中再開を実装し、部分修正で全素材を再生成しない。

MVP対象外はWebサービス、クラウド実行、複数ユーザー管理、アニメーション、キャラクター立ち絵・口パク、自律的なLLM呼び出し、独自TTSモデルの学習。一般公開やアップロードも動画生成とは別操作とする。

## macOSの依存関係と起動確認

必要なものはNode.js、FFmpeg/ffprobe、Playwright用Chromium、VOICEVOXアプリ。Node.jsの対応バージョンとnpm依存は実装開始時に検証して固定し、lockfileをcommitする。

既存VOICEVOXアプリにはHTTP APIを提供するエンジンが含まれる。ユーザーのMacでAPIドキュメントを開けることは確認済みで、別のHTTP版の導入を前提にしない。

```bash
curl http://127.0.0.1:50021/version
open -a VOICEVOX
```

- 接続先は `VOICEVOX_URL`、初期値は `http://127.0.0.1:50021`。
- doctorコマンドで依存の存在・バージョン・Chromium起動・エンジン応答を確認する。
- 未起動時はmacOSの `open -a VOICEVOX` で起動し、有限の待機時間で応答を確認する。上限超過は修復方法付きのエラーとする。
- `/speakers` から話者・スタイルを解決する。ずんだもんのIDを永続的な定数とせず、実行記録に解決結果を保存する。
- ユーザーが起動したVOICEVOXを処理後に終了しない。
- インストール済みFFmpegが字幕描画に必要なlibassフィルターを持つこと、日本語フォントが読めることを検査する。

## アーキテクチャ

1. エージェントが質問の範囲・対象読者・根拠を整理する。
2. 調査結果を説明項目とスライドに組み立て、story.jsonを生成する。
3. CLIがschemaと根拠参照を検証する。
4. HTMLを描画し、密度・はみ出しを検査する。
5. 違反があれば該当IDと理由をエージェントへ返す。エージェントが内容を分割・修正する。
6. 確定原稿からTTSを生成し、実測時間から共通タイムラインを作る。
7. スライド画像・音声・字幕を合成し、完成物を検証する。

CLIは文章の意味を自動で書き換えない。原稿・レイアウト修正の責任はエージェント、計測・同期・書き出しの責任はCLIに置く。自動修正は初期上限3回とし、残る違反を黙って通さない。

## リポジトリ調査と根拠

- 調査対象のリポジトリURLとcommit SHAを固定する。ローカルに未commit変更がある場合はその有無と差分の識別情報も記録する。
- AGENTS.mdなど対象リポジトリの適用指示を読み、入口、呼び出し関係、条件分岐、データ更新、戻り値、副作用、例外を追う。
- spec、実装、テストを区別する。テストが存在することと、実際に実行して通ったことも区別する。
- 各主張にsource IDを付け、ファイル・行範囲・commit固定URLへ紐づける。
- specと実装の不一致、未確認の挙動、推測した設計意図は明記する。
- 一般概念では公式資料のURLと参照日、検算した具体例を根拠にする。
- 教材生成だけのために対象リポジトリのコードや依存を自動実行しない。実行検証が必要なら既存の権限と指示の範囲で行う。

## 中間データ

バージョン付きschemaを定義し、ランタイムで入力を検証する。主要なデータは次の3層に分ける。

| データ | 内容 |
| --- | --- |
| story.json | 質問、対象読者、調査対象、根拠、説明項目、スライド、原稿、テーマ、音声設定 |
| timeline.json | 実測音声時間、音声・字幕の開始終了、スライドのフレーム範囲 |
| manifest.json | 入出力ハッシュ、ツール・エンジン・テーマのバージョン、生成時間、検証状態 |

各スライドは安定したid、layout、title、主張・図・コードなどの構造化content、narrationの配列、evidence参照、前後のgapを持つ。narrationの各要素は安定したsegment IDと原文textを持つ。

字幕本文の正本はnarration.text。字幕生成のための再要約はしない。読み辞書は発音だけを調整し、画面のAPI名などの綴りは維持する。任意HTML・CSSを入力で許可せず、テキストはエスケープする。

音声アダプターはtext、voice、speedを受け取り、audioPathとクレジット情報を返す。時間計測は共通処理にする。VOICEVOX固有の合成クエリや辞書操作はアダプターに閉じ込める。

## Design Systemとページ分割

初期値は以下。最終的には実際の動画をMacとスマートフォンの視聴サイズで評価して調整する。

| 項目 | 初期値・制約 |
| --- | --- |
| キャンバス | 1920×1080、16:9 |
| タイトル | 64px以上 |
| 本文 | 40px以上 |
| コード | 32px以上。長いコードは意味の通る抜粋にする |
| 字幕 | 44px以上、最大2行 |
| 主張 | 原則1スライド1主張 |
| 字幕領域 | 下部に専用の行領域を確保し、本文が侵入しない |
| 配置 | 通常フロー、Grid、Flex。absolute/fixed、負の余白やtransformによる配置回避は禁止 |
| 色・余白 | 共通tokenで管理。文字のコントラストを確保する |

HTMLは字幕用の空き領域を含めて撮影する。FFmpegの字幕位置は同じthemeの座標・余白定義から計算し、本文に重ねない。

固定フォントを同梱する場合は配布条件を確認し、ライセンスを保持する。フォント読み込みと画像decode完了を待って撮影し、アニメーションを無効化する。

DOMのscroll寸法とbounding boxで、画面外・親領域外・テキストの切れを確認する。最小文字サイズ、禁則配置、字幕の実描画行数も検査する。overflow:hiddenで隠しただけの要素も合格にしない。

収まらない場合は同じテンプレートで内容を分け、必要なら文脈を示すタイトルを付ける。分割で原稿の欠落・重複や根拠参照の消失を起こさない。

## 音声・字幕・タイムライン

VOICEVOXの `/audio_query` → `/synthesis` でWAVを生成する。原稿を自然な短文に分割してから合成し、ffprobe等で音声時間を実測する。短文が字幕2行に収まるかはTTS前に検査する。

短文単位の方式は字幕同期を単純化する一方、抑揚が途切れる可能性がある。初期試作で自然さを評価する。改善が必要な場合のみ、スライド単位合成とタイムスタンプ／forced alignmentを検討する。文字数比例で時刻を推定しない。

```text
スライド尺 = 前のgap + 結合音声の実測時間 + 後のgap
初期gap = 前1秒、後1秒
例: 音声10秒 → 12秒、次の音声20秒 → 22秒、合計34秒
```

- ENGINE側が出力に含める無音も実測時間に含まれる。前後音素長を明示的に管理し、意図しない二重の無音を避ける。
- 文間の間を追加する場合、その時間も音声・字幕の共通タイムラインに含める。
- 生成音声は共通サンプルレートへ揃え、WAV/PCMで結合して最後にAAC化する。短文ごとのAAC結合による隙間を避ける。
- 映像は整数フレーム、音声は整数サンプルで管理する。スライド尺を30fps境界へ切り上げ、必要な微小無音を追加し、その確定尺を全出力で共有する。
- 字幕は各短文の発話区間に表示し、前後gapでは空にする。表示延長を導入する場合も次の字幕と重ならない規則を定義する。
- ASSを焼き込み用に生成し、再利用用SRTも出す。原稿と字幕は改行等の表示上の差を除いて一致させる。
- クレジット `VOICEVOX:ずんだもん` を最終ページ等に自動挿入する。キャラクター画像はMVPでは使用しない。実装時に公式規約を確認する。

## キャッシュ・再開・エラー処理

- TTSキー: 原文、発音辞書ハッシュ、音声・スタイル、速度など全合成設定、ENGINE/モデルの識別情報。
- 画像キー: スライド内容、テーマ、フォント、レンダラーのバージョン。
- 音声再生成で時間が変われば、後続字幕の時刻と最終動画を再計算する。変わらない画像は再利用する。
- 原稿変更なしの見た目修正でTTSを再生成しない。
- 完了済み素材を保持し、失敗ステージから再開できるようにする。書き出しは一時ファイルから原子的に確定する。
- VOICEVOXの並列数は初期1とし、実機計測後に設定可能にする。無制限並列化しない。
- 外部プロセスは引数配列で呼び出し、原稿をshellコマンドへ展開しない。
- 成果物とcacheは対象コードリポジトリの外に置き、意図せずcommitしない。

## 提案ディレクトリ構成

```text
dopagaki-wiki/
  package.json
  src/
    cli/
    schema/
    slides/
    speech/
    timeline/
    video/
    validation/
  assets/
    themes/
    fonts/
  skills/dopagaki-wiki/
    SKILL.md
    references/
      research.md
      storytelling.md
      design-system.md
  tests/fixtures/
  docs/implementation-plan.md
```

skillはこのリポジトリを正本にしてGitで管理し、macOSのskillディレクトリへの導入方法を実装時に用意する。CLIの所在を明示し、skillだけコピーして実行不能にならないようにする。SKILL.mdには調査・構成・修正判断・CLI起動方法を書き、詳細はreferencesへ分ける。

提案CLI: `doctor`、`validate <story>`、`preview <story>`、`render <story> --out <directory>`。最初はこの4つに絞り、再開・キャッシュはrender内部の機能とする。

## 実装順序と受け入れ条件

### Phase 1: 垂直スライス

- [ ] TSプロジェクト、schema、doctor、1つのHTMLテンプレートを作る。
- [ ] 2スライドの固定原稿でVOICEVOX生成、画像撮影、時間計測、字幕付きMP4まで通す。
- [ ] 前後各1秒のgapと発話区間の字幕を確認する。
- [ ] 実機で各処理の時間を記録する。

完了条件: Mac上でずんだもんの音声付きMP4を再生でき、字幕と音声が一致する。ここで音声の短文分割の自然さを判断する。

### Phase 2: 教材用レイアウト

- [ ] 5テンプレートと共通themeを実装する。
- [ ] 字幕専用領域、文字サイズ、オーバーフロー検査を実装する。
- [ ] 長い日本語、長い識別子、コード、比較表のfixtureを作る。
- [ ] 検査違反をslide/segment ID付きで出力する。

完了条件: 過密なfixtureは具体的な理由で失敗し、意味を保って分割すると合格する。文字縮小やクリップで合格させない。

### Phase 3: 調査とskillの接続

- [ ] 根拠schema、commit固定参照、未確認・推測の表現を整備する。
- [ ] skillから調査 → story → 検査 → 修正 → 動画出力を実行できるようにする。
- [ ] 回答すべき項目のcoverageをレビューする。
- [ ] リポジトリ機能の説明と「2進数と10進数の違い」の両方を試作する。

完了条件: 実装についての主張を根拠に戻って確認でき、一般概念でも同じCLIを使える。音声だけ／無音字幕の両方で説明が成立する。

### Phase 4: 再生成と仕上げ

- [ ] 素材キャッシュ、途中再開、有限retry、エラー案内を実装する。
- [ ] manifest、原稿、根拠一覧、SRT、HTMLプレビューを成果物にまとめる。
- [ ] 初回と再実行の計測結果を比較する。
- [ ] macOS導入手順とskillの参照先を確認する。

完了条件: 見た目だけの変更でTTSを再生成せず、1文の変更で該当音声と必要なタイムラインを更新できる。VOICEVOX停止や依存不足で明確なエラーを返す。

## 品質ゲート

枚数を主要な品質指標にしない。質問への結論、必要な前提、仕組み、具体例、制約・例外が必要な深さで説明されていることを確認する。minSlidesは任意設定として追加可能にするが、未指定なら固定下限を設けず、水増ししない。

| 検査 | 受け入れ条件 |
| --- | --- |
| 根拠 | 実装に関する主張に参照があり、参照先と内容が一致する |
| 内容 | 質問に回答し、重要事項の省略や同じ内容の水増しがない |
| 視認性 | 最小文字サイズ、画面内配置、本文と字幕の分離を満たす |
| 字幕 | 原稿と一致し、2行以内、時刻は単調で範囲外・重複なし |
| 時間 | 合計尺が共通タイムラインに一致し、許容差は1映像フレーム＋音声codecのpaddingに限定 |
| 音声 | 欠落・切断・明らかな読み違いがない。API名等の代表語を試聴 |
| 再生 | MP4をデコードでき、Macで冒頭・中間・末尾を再生確認する |
| 視聴体験 | 全スライドの一覧と字幕付き代表フレームを確認し、実際の視聴サイズでも読める |

タイムラインのテストは長い動画、端数秒、音声変更時の後続字幕更新を含める。10秒と20秒のPCM fixtureで合計34秒になる例を検証する。実VOICEVOXの音声はその長さを決め打ちしない。エージェントによるレビューは同じ実行内で行い、サブエージェントを必要条件にしない。
