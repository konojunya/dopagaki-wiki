# 動画生成の比較記録

ここには、実装やSkillの変更が説明の品質・生成速度に与えた影響を、後から比較するための記録を保存する。

通常の動画作成では、調査記録・原稿・画像・動画・検査結果を `/tmp` に作り、対話で共有する。ユーザーがGitへの保存を依頼した場合、または開発タスクで比較記録を残す方針が明示されている場合だけ、このディレクトリへ必要なものを選んで追加する。テストやCLIの実行だけで自動保存しない。

## 保存先と更新方法

新しい記録は `docs/generation/<CLIバージョン>/<UTC日時>-<比較内容>/` に置く。CLIバージョンは生成に使った `package.json` の `version`。同じバージョンでの改善も別ディレクトリへ追加し、記録のためだけにバージョンを上げない。

```text
docs/generation/
  README.md
  0.0.1/                         # 最初の比較基準。従来の配置を保持
    README.md
    video.mp4
    ...
    20260910T030000Z-caption-spacing/
      README.md
      comparison.json
      quality-review.md
      ...
```

- 日時は評価した実行を識別するためのもの。比較内容には `caption-spacing` など短い英数字名を使う。
- 既存の動画・原稿・計測結果を上書きしない。再生成は新しい一時ディレクトリで行う。
- 新しい記録を追加したら、下の一覧にリンク・比較元・評価結果を1行追加する。
- 記録の誤りを訂正する場合は理由を明記する。再計測値で過去の測定値を置き換えない。
- 過去の記録にある依存関係は生成当時の情報。現在の導入は [セットアップ](../setup.md)、テスト手順は [開発と検証](../development.md) を使う。

## 保存するもの

| ファイル | 内容 |
| --- | --- |
| `README.md` | 依頼内容、比較した変更、結論、動画へのリンク、再実行コマンド、保存省略の理由 |
| `comparison.json` | 比較元の記録パス、変更前後の実装commit、実行日時、使用モデル・推論設定（不明ならnull）、原稿・動画・デザイントークンのSHA-256、動画のバイト数 |
| `story.json`, `evidence.json`, `script.md` | 原稿・説明項目・根拠。入力画像があれば入手元とともに相対パスを保って保存 |
| `manifest.json`, `layout-report.json`, `validation.json` | 生成条件、実装・入力・動画のハッシュ、機械検査結果。生成された内容を加工しない |
| `timeline.json`, `subtitles.srt` | 実音声に基づく時間と字幕 |
| `quality-review.md` | 下記の同一基準による変更前後の評価、根拠フレーム・時刻、未検証事項 |
| `benchmark.json` | 性能に関する変更なら必須。測定条件・回数・各実行値・キャッシュ利用・計測範囲 |
| `contact-sheet.png`, `review/` | 全スライド一覧と、比較箇所がわかる必要最小限の代表フレーム・検査レポート |
| `video.mp4` | 下記の容量上限を満たす完成動画 |

実装commitには生成したコードのcommitを記録し、記録ファイルを追加したcommitと区別する。未commitのコードで評価した場合は差分とそのSHA-256も保存する。モデル・ハードウェア・エンジン等の不明な条件を推測で埋めない。原稿のパス等を保存時に変更する必要があれば、生成時の入力と変更後の入力のハッシュを区別して記録する。

## 比較の基準

原則として同じ質問・同じ `story.json` を使う。原稿・画像・モデル・VOICEVOX・フォント・FFmpeg・ハードウェア等も変わった場合は差分を明記し、結果を実装変更だけの効果と断定しない。比較元の実装を再実行した場合も別の記録として残す。

`quality-review.md` では、次を「比較元の結果 / 今回の結果 / 改善・同等・悪化・未検証 / 根拠」の表にする。根拠のない総合点は付けない。

1. **説明の正確さ・網羅性**: 質問と説明項目への回答、数値・コード・図の根拠、説明漏れや誤解を招く箇所。
2. **視認性**: 全ページ、字幕付き代表フレーム、844×475での可読性。色・コントラスト・文字サイズ・はみ出し。
3. **音声・字幕**: 欠落・クリッピング、用語の読み、字幕本文と表示時刻。機械検査・ENGINEカナ確認・人の試聴を区別する。
4. **生成物の成立**: 1920×1080 / 30fps / H.264・AAC、尺・フレーム数・全編デコード、再生確認。
5. **速度・再利用**: 初回・再実行・見た目のみ変更・1文変更の時間とキャッシュヒット。品質を落とした短縮は明記する。

初回はその測定専用の空キャッシュ、再実行は同じ入力とそのキャッシュを使う。既存の利用者キャッシュを消さない。測定回数と個々の値を残し、複数回なら中央値も示す。CLI処理時間と調査・原稿作成・初回依存導入・レビュー時間を区別する。未計測の項目や、異なる条件での比較はその旨を示す。

## 容量とGitへの追加

このリポジトリの保存上限は **MP4単体40 MiB、1記録の追加ファイル合計100 MiB** とする。追加前に実ファイルのサイズを確認する。Git LFSは導入しない。

上限を超える動画はGitへ追加せず、サイズ・SHA-256・省略理由・再生成方法を記録する。代表画像と品質・性能レポートは残す。保存のために検証済み動画を再圧縮して別物に置き換えない。`/tmp` の共有リンクだけを恒久的な再評価資料と見なさない。

中間WAV、キャッシュ、依存パッケージ、全フレーム、重複フォントは保存しない。HTMLや全スライドPNG、追加の検査画像は、その比較に必要な場合のみ容量上限内で追加する。初期の `0.0.1` に保存済みの資料は保持する。

生成と評価を `/tmp` で完了し、必要なファイルだけをコピーする。差分に個別プロジェクトの秘密情報や不要なファイルが混ざっていないこと、リンクとハッシュが保存対象と一致することを確認し、記録をcommitしてpushする。実装commitと評価記録commitを分けると、後から生成に使った状態へ戻しやすい。
