# 質問が動画になるまで

このリポジトリを読んで、質問してから、ずんだもんの動画が完成するまでを初めて使う人向けに説明して。エージェントとプログラムの役割を図で示し、台本修正時の再利用も説明して。

## 質問から動画へ、３つの役割

質問が動画になるまでには、三つの役割があるのだ。

まずエージェントが調べて台本を作り、プログラムが映像と音声にするのだ。

最後にエージェントが内容と見た目を確認し、動画を共有するのだ。

根拠: skill, runner

## 最初に伝えるのは、知りたいこと

今回の依頼は、このツールの仕組みを、初めての人向けに説明することなのだ。

エージェントは指定されたコードを読み、実際の処理をたどるのだ。

利用者が台本のデータを手書きする必要はないのだ。

根拠: skill

## 台本データが、処理への受け渡しになる

調べた内容は、ページごとの図、文章、読み上げる文に整理するのだ。

その受け渡しに使うのが、ストーリー・ジェイソンという台本データなのだ。

プログラムは項目や参照先を検査するけれど、説明の正しさは根拠と照らして確認するのだ。

根拠: skill, input

## 見た目は、共通のルールで揃える

スライドは、共通の配色や書体と、決まったレイアウトで描くのだ。

ブラウザーで表示して、文字のはみ出しや、字幕が二行以内かを実測するのだ。

モデルが変わっても見た目のルールは揃うけれど、説明の内容には差が残るのだ。

根拠: slides, design

## 字幕の時刻は、できた音声から決める

次に、ボイスボックスが文ごとに、ずんだもんの音声を作るのだ。

できた音声の長さを測り、その文を表示する開始時刻と終了時刻を決めるのだ。

字幕には読み上げと同じ文章を使うので、別の要約に置き換わらないのだ。

根拠: voice, timing

## 合成して検査し、動画を共有する

画像、音声、字幕をエフエフエムペグで合成すると、一本の動画になるのだ。

プログラムが形式や音量を検査し、動画を最後まで読み込めることも確認するのだ。

ただし機械検査だけでは、説明の正しさや声の自然さまでは証明できないのだ。

確認した動画と台本は、作業用フォルダーに保存して対話で共有するのだ。

根拠: movie, runner, skill

## 作り直しのために、素材を保存する

作り直すときのために、画像と音声と完成動画を、別々に保存しているのだ。

この保存物をキャッシュと呼び、同じ条件なら再利用するのだ。

ファイルの中身も照合するので、壊れた保存物は作り直すのだ。

根拠: slides, voice, movie

## 読み上げる１文だけを直したら？

例えば、三つの文のうち、二つ目の読み上げだけを直すのだ。

画面と声の設定が同じなら、画像と、変えていない文の音声を再利用できるのだ。

変えた文は音声を作り直し、字幕と時刻を組み直して、完成動画を再合成するのだ。

根拠: voice, slides, movie

## 直す場所によって、再利用するものが変わる

画面の説明だけを直した場合は、音声を再利用して、変えた画像と動画を作り直すのだ。

何も変えず条件も同じなら、完成動画も再利用できるのだ。

再利用した場合も検査は行い、使える素材を残しながら説明を改善していけるのだ。

根拠: slides, voice, movie, runner
