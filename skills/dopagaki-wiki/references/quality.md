# 品質の確認と記録

`validate` は構造、根拠の参照、説明項目の対応を検査する。`preview` はさらにフォント、本文・親・画面のはみ出し、禁則配置、字幕2行以内を Chromium で実測する。`render` は音声の実サンプル数からタイムラインを作り、原稿一致、範囲内・非重複の字幕、1080p/30fps/H.264/AAC、合計尺、全編デコードを確認する。

字幕が変わる時刻ごとに映像フレームが必要。FFmpeg は必ず fps=30 → ASS描画 → encode の順に処理する。静止画だけをASSに渡して最後にフレーム複製すると、字幕が更新されない。

ツールの実装変更時は、ツール側リポジトリで `npm run check` と `npm test` を実行する。生成処理・音声・キャッシュを変更した場合は、VOICEVOXに接続して `npm run test:e2e` も実行し、動画生成、差分更新、キャッシュ破損からの復旧、字幕表示、音声波形を検証する。これらはNode.jsと通常の動画生成環境で動作し、Go・Python・uvを必要としない。教材固有のコード検算は、説明対象に応じた環境で別途行う。

機械検査の後に、以下を quality-review.md に記録する。

1. 質問への結論、前提、仕組み、例、制約の coverage。公式根拠と検算結果。
2. 全ページ一覧と、字幕付きの冒頭・中間・末尾。コード・数字・図の正確さ、844×475での視認性。
3. 音声の欠落・切れ・用語の読み。人の試聴、音響検査、ASR照合を混同しない。音声認識による照合は同梱していない。別の利用可能な手段でASRを使う場合も補助検査として記録し、自然さや抑揚の証明にはしない。
4. 実動画の再生と、manifest / validation.json の結果。スライドPDFはページ数・順序・図・日本語の表示を確認し、字幕と灰色の帯が入っていないことを確認する。`manifest.pdf` にPDFのハッシュ・ページ数・バイト数・生成時間を記録する。
5. 初回・再実行・見た目のみ変更・1文変更の生成時間とキャッシュヒット。ハードウェアやエンジン、ブラウザーの条件。

再評価用の記録では、評価した videoSha256 と storySha256、コードのcommit、変更点、同じ基準の評価結果を残す。未検証事項は未検証と書く。合格だけのチェック欄で意味的な品質を代用しない。
