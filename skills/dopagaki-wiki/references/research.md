# 調査と根拠

一般概念では公式仕様・公式ドキュメントを参照し、URL、参照日、どの主張を支えるかを `sources` に残す。数値やコードは小さな独立例で検算する。調査した時点と実際に検証したバージョンが違えば両方記録する。

リポジトリ説明では対象 URL、40桁 commit SHA、未コミット変更の有無と差分ハッシュを固定する。適用される AGENTS.md を読み、入口・呼び出し・条件・状態更新・戻り値・副作用・例外を追う。`implementation` / `spec` / `test` / `inference` を区別する。実装・テストの source はファイル・行範囲・revision・commit固定URLが必須。テストは `executed: true/false` を明記する。

推測や未確認事項は source.note と画面または原稿で明示する。推測した設計意図を実装上の事実に変えない。対象コードを教材作成のためだけに自動実行しない。自分で用意した検算用の独立例は、既存の実行権限の範囲で検証する。

各ページの `claim` と `evidence` が対応しているか、引用先を開いて確認する。CLI は ID の存在と参照形式を検証できるが、文章の真偽や引用の含意までは判定しない。結論・前提・仕組み・具体例・例外を `objectives` に対応させ、どこで質問に答えたか説明できるようにする。
